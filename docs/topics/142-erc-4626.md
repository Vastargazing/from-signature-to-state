# ERC-4626: Tokenized Vaults

> **ERC-4626 standardizes vault shares representing a claim on one underlying ERC-20 asset. The exchange rate carries yield, loss, fees, and rounding.**

## Assets and shares

A user deposits an underlying **asset** and receives vault **shares**:

```text
deposit assets → mint shares
burn shares    → withdraw assets
```

Shares themselves follow ERC-20. Their value comes from the vault's managed assets and conversion rules.

If a strategy earns yield while share supply stays constant, each share can redeem for more assets. Losses or fees can move the rate the other way.

## Paired operations

The standard separates exact-input and exact-output intentions:

- `deposit(assets)` chooses exact assets in and returns shares;
- `mint(shares)` chooses exact shares out and returns required assets;
- `withdraw(assets)` chooses exact assets out and burns shares;
- `redeem(shares)` chooses exact shares in and returns assets.

Preview functions estimate the corresponding result under current on-chain conditions. Max functions report user or protocol limits.

## Standard interface, variable risk

ERC-4626 does not specify the investment strategy, safety, withdrawal liquidity, fees, or governance. A vault can lend, stake, hold idle assets, or be malicious while exposing the same interface.

Integrators must handle rounding and slippage in the direction appropriate to each operation.

## Inflation and donation attacks

In a nearly empty vault, an attacker may donate assets directly and manipulate the assets-per-share ratio so a victim's small deposit rounds to very few or zero shares.

Defenses include virtual assets and shares, minimum liquidity, slippage bounds, and careful rounding. The standard creates common semantics but does not erase implementation attacks.

Do not use an easily manipulated preview conversion as a trusted external price oracle.
