# EIP-7702

> **EIP-7702 lets an EOA delegate its behavior to contract code while keeping its existing address, key, balance, and storage.**

## The delegation

The EOA signs an authorization naming a contract implementation. A new transaction type applies that authorization by placing a delegation marker in the EOA's code field.

Calls to the EOA can then execute the delegated implementation in the EOA's own account context. This enables features such as batching, sponsorship, permission checks, and guardian-assisted operation without moving every asset to a new address.

```text
same EOA address + delegated code → programmable behavior
```

The authorization includes a nonce and a chain identifier; chain ID zero deliberately makes an authorization valid across chains, while a specific chain ID scopes it. The EOA's private key still has protocol-level power to send ordinary transactions and create, replace, or clear delegations.

Delegated “recovery” cannot rotate the protocol's ECDSA key. Code can let guardians replace an application-level signer or continue operating the account after key loss, but anyone who later obtains the original key can still override the delegation or transact directly.

## Not the same as ERC-4337

EIP-7702 changes the Ethereum protocol account model. ERC-4337 is a contract-based operation pipeline using UserOperations, bundlers, and EntryPoint.

They can work together: a delegated EOA may use wallet code compatible with 4337. But neither proposal automatically requires the other.

## New power, new signing danger

An authorization can delegate control to malicious code. A signature that looks like “enable a feature” may effectively install logic able to move assets or approve spenders.

Wallets must show the implementation, chain scope, nonce, permanence, and revocation path clearly. The delegated implementation must handle initialization and storage carefully, because it runs at an address that may already hold assets and state.

Changing or clearing delegation does not undo calls already made, approvals already granted, or assets already stolen.

## The mental model

Traditional EOA: fixed signature behavior. EIP-7702 EOA: the key can select code that defines richer behavior at the same address.
