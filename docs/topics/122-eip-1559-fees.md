# EIP-1559: Base Fee, Priority Fee, and Burning

> **EIP-1559 gives every block a protocol base fee, lets users add a validator tip, and burns the base-fee portion.**

## Three transaction settings

A modern Ethereum transaction can specify:

- `maxFeePerGas`: absolute ceiling per gas;
- `maxPriorityFeePerGas`: maximum tip per gas;
- `gasLimit`: maximum gas units the execution may use.

The block provides `baseFeePerGas`.

For each gas unit actually used:

```text
effective priority = min(max priority, max fee - base fee)
effective price    = base fee + effective priority
```

The transaction cannot be included if its fee cap is below the block's base fee.

## Who receives what

The base fee is burned by protocol rules. The priority fee goes to the block's fee recipient, normally chosen by the proposer or its block-building arrangement.

Any unused difference under the sender's maximum cap is not paid. `maxFeePerGas` is a ceiling, not a bid that is always fully charged.

## Why burn the base fee

If the producer directly received a protocol-computed minimum fee, it would have stronger incentives to manipulate demand or include self-paid transactions to influence it.

Burning separates congestion pricing from the producer tip and gives ETH a protocol-level fee sink.

It does not burn the whole transaction payment. Tips remain revenue, and MEV can provide additional off-protocol or in-protocolized value to builders and proposers.

## What EIP-1559 improved

Before EIP-1559, wallets mainly guessed a first-price auction bid. EIP-1559 made the minimum price predictable from recent blocks and added elastic space above a target.

It did not guarantee cheap fees. When demand persistently exceeds capacity, the base fee rises until some users wait, move, or pay.

```text
better fee estimation ≠ unlimited cheap block space
```
